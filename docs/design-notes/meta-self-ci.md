**`ci.yml`** — meta's own CI:

- Matrix checks via `mise-task.yml`: Actionlint, Mise Tasks, ShellCheck. Plus Secret Scan (`ci:betterleaks`) and Deep Secret Scan (`ci:trufflehog`), and the hosted self-validation jobs below. The local gate `mise run all` additionally covers `iac:zizmor`, `iac:trivy` and `ci:meta-semgrep`.
- ShellCheck is fail-closed: it enumerates every tracked task/helper plus `.github/scripts/github-actions-scanner.sh` and accepts only stage-0 regular non-symlinks with mode 100644/100755 before analysis.
- **`Zizmor Action`** — pins the official action and the reviewed Zizmor image mapping at the versions in `ci.yml`; online audits / Advanced Security / SARIF / annotations disabled. The action hands the Zizmor process a fixed public compatibility placeholder that is **not** a credential and carries no permissions; no GitHub credential reaches that process. Checkout uses the job's `contents: read` token with `persist-credentials: false`. This early-development gate is **not** fully offline or network-isolated — residual container egress and raw CLI log output are accepted, with final PR CI as runtime proof. It replaced the old matrix `Zizmor` **check name** but not the local gate: coordinate any org-ruleset required-check rename with `Zizmor Action`.
- **`Grype Path (high, fixed)`** — pins scan-action and Grype at the versions in `ci.yml`, uses a nested exact-SHA target and a trusted mode-0600 config, blocks fixed High/Critical findings and operational/cleanup failures, and does not cache or upload SARIF. Medium and unfixed findings are outside policy.
- **`GitHub Actions Scanner (experimental)`** — pins a Snyk Labs commit + lock digest, installs tokenlessly with lifecycle scripts disabled, runs only the production rules listed in the job's `rules` array. Findings and failures are informational (`findings` / `incomplete`, never a false `clean`); fork, Dependabot, untrusted-association and unsupported-event paths are tokenless `incomplete` with no SHA fallback. Only non-Dependabot push/`workflow_dispatch`, or same-repo OWNER/MEMBER/COLLABORATOR PRs, may pass the current-repo token to the exact Node child. Raw output and the token are never summarized; source/cache/result cleanup failure blocks the job. Snyk source updates are manual source/support/lock/baseline reviews.
- Renovate groups Zizmor action+CLI and Anchore action+Grype; neither automerges.
- `ci:meta-semgrep` in `mise.toml` retains `p/ci` and replaces only its Renovate minimum-release-age rule by exact rule ID. `.opengrep/renovate.yml` requires at least three days, rejects disabled waits, and keeps the upstream integer-day format requirement. Package rules inherit a top-level default or the sole `github>nics-dp/meta:renovate-preset` extension with no `ignorePresets`; the local preset is scanned for its default and explicit overrides too. This is a check of meta's known preset relationship, not a general remote preset resolver. Property names must be unescaped because OpenGrep preserves Unicode escapes instead of decoding them. Checks cover `renovate.json`, `.renovaterc.json`, and `renovate-preset.json`, including leading line/block comments. JSON5-named and extensionless configs are outside this policy's supported scope; the pinned scanner's directory scan does not apply the upstream JSON Renovate rule to those files either. Renovate scheduling and the shared `ci:semgrep` atom are independent and unchanged. Run `python3 .github/tests/test_opengrep_renovate.py` for executable policy and baseline coverage.

**`self-supply-chain.yml`** — meta consumes its own `scorecard.yml` (filtered, `publish: false`). No dependency-submission job: meta has no compiled-language manifests.

**`self-dependency-review.yml`** / **`self-pr-issue-check.yml`** — meta consuming its own `dependency-review.yml` / `pr-issue-check.yml` reusables.

**`license-inventory.yml`** — weekly org-wide license check: a ci-read App token scoped to `contents: read` reads every installation repository's dependency-graph SBOM, `.github/scripts/license-inventory.py` evaluates each SPDX expression against the `deny_licenses` default in `dependency-review.yml` plus the workflow's `INVENTORY_ONLY_DENY`, and one issue in this repository is opened or updated when a dependency hits or a repository's SBOM cannot be read (skipped, not clean), and closed when neither happens.

**`lib-dead-code.yml`** — weekly cross-repository dead code report for the Go libraries (libdcf, ZenQuery). `go:dead-code` roots at main packages, so on a library alone it calls every exported function unused, and `--whole-program` only adds the library's own tests as roots. `.github/scripts/lib-dead-code.py` answers the question across repositories instead: with a ci-read App token scoped to `contents: read` it shallow-clones every installation repository that has a root `go.mod` (its `dev` branch, else the default branch), writes a `go.work` joining the library modules and every module outside the library repositories that requires one, and runs deadcode once per consumer for its production build and once for its `-tags test -test` build. A library function is listed only when every successful build either never compiles its file (the package is not loaded, or a build tag such as `test || integration` excludes the file) or leaves the function unreached, so a build that never type-checked a function cannot vouch for it; a library package no build loads is listed whole, and a file of an imported package that no successful build compiles (a platform or build-tag file; `//go:build ignore` files excepted) is listed as not analysed, since deadcode never judged its functions. With anything not analysed, the report limits its conclusion to what was analysed, and a library repository it cannot fetch still produces a report instead of an exit. A GitHub API error other than HTTP 404 lists the repository as not analysed instead of treating it as absent, so a rate limit or 5xx never drops a consumer silently. The libraries' own `test/` packages and generated files are left out. A build that does not load (typically a consumer whose test mocks no longer satisfy the library's current interfaces) is listed as not analysed, since what only it uses then shows as unused. It clones rather than reading the GitHub source archive because the repositories' `.gitattributes` marks tests and build assets `export-ignore`. The go.work takes the highest `go` line and toolchain among its members, and deadcode is built with that toolchain at the version pinned in the `go:dead-code` atom header, so its type checker reads every member's source. The report opens or updates one issue in this repository and closes it when nothing is found and every build loads. It is never a pull request gate: whether a library function is used depends on consumers, so a consumer change alone could turn a library pull request red.
